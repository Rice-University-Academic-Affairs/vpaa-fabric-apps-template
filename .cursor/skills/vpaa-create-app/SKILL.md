# Create a VPAA Rayfin app

Rayfin 1.36.2 / Universal App notes: https://rayfin.ai/docs/reference/cli/templates and https://rayfin.ai/docs/reference/agent-rules

Do not run `npm create @microsoft/rayfin` into `apps/`. Rayfin's `blankapp` (canonical hidden name `universal-app`) scaffolds a React+Vite workspace with capability packs. VPAA keeps SvelteKit + `adapter-static` and copies those principles: data first, then functions/connectors/storage; exact-version `@microsoft/rayfin-*` from the pnpm catalog (currently 1.36.2); no `RAYFIN_FEATURE_FLAGS` except experimental `storage`. Never `npx rayfin`. Deploy with `pnpm up-app <slug>` from the repo root (see `vpaa-up-app`).

Collect if missing: kebab-case slug; semantic-model portal URL when there is no SQL; Fabric workspace **name** (the string in the portal, not only the GUID) when they want it published. `rayfin up --workspace` takes that name.

1. Ask for a kebab-case slug if missing. Refuse existing `apps/<slug>` or package names. If the user asked to recreate an existing slug, delete `apps/<slug>` first, then continue.
2. From the repo root:

- SQL / Rayfin GraphQL: `pnpm new-app <slug>`
- Semantic model, no Rayfin SQL: `pnpm new-app <slug> --semantic`
- Semantic model with `fabric.yaml` from a portal URL: `pnpm new-app <slug> --semantic --from-url "<Fabric URL>"`
- Enable backend Functions (off by default until the tenant has Functions): `pnpm new-app <slug> --functions`
- Product pages without AppShell (admin still uses the shell): `pnpm new-app <slug> --blank`

`--from-url` implies `--semantic`. `--fabric` and `--semantic` are mutually exclusive. `--fabric` runs `rayfin init --services db` (MSSQL). Do not use `--fabric` when the user wants no SQL. Do not run `az login` or `fabric-app-data add` to fill `fabric.yaml`; `--from-url` writes workspace and item IDs from the URL.

3. Confirm `apps/<slug>` has the script contract (`dev`, `dev:frontend`, `dev:rayfin`, `check`, `test`, `test:smoke`, `test:e2e`), `AGENTS.md` with the Dev/Test/Smoke/E2E/Check/Generate headings, a single-server `playwright.smoke.config.ts` on 5173, `@vpaa/*` workspace deps, `adapter-static`, and `rayfin.yml` with `buildCommand: npm run build:fabric`, `assetAccess: protected`, and `externalEntraExchange: true`. `dev` stays `PUBLIC_ADMIN_TEST_MODE` Vite so smoke boots without Fabric. `dev:frontend` is what `rayfin dev` starts. `dev:rayfin` runs `rayfin dev`. Do not add the slug to `.gitignore` or negate it in `pnpm-workspace.yaml`; every app under `apps/` is first class. For `--semantic`, also confirm `services.data.enabled: false`, `@vpaa/semantic`, and `build:fabric` runs `node scripts/fabric-app-data.mjs generate`. For `--from-url`, also confirm `fabric.yaml` has the workspace and item IDs from that URL. For `--functions`, confirm `services.functions.enabled: true`, `auth.type: application`, `path: rayfin/functions`, and `host.json` extensionBundle `[4.49.0, 5.0.0)`.
4. Add any product UI the user asked for (home page, queries, tests). Then run `pnpm --filter @vpaa/<slug> test` and `pnpm --filter @vpaa/<slug> test:smoke`. For semantic DAX loaders: `readSemanticModelTable` returns Arquero (`result.table.objects()`). `querySemanticModel` returns a raw Fabric `QueryTable` (`result.table.columns`, `result.table.rows`). Never call `.objects()` on a `querySemanticModel` result — that throws `TypeError: table.objects is not a function` and the Fabric embed shows a 500.
5. Import entity decorators from `@microsoft/rayfin-core` (not `/experimental`, except `blob`). Import `Source` / `AutoGenerated` from `@microsoft/rayfin-connectors`. Import `ConnectorsRayfinClient` from `@microsoft/rayfin-client`. Do not set `useProxy` on `RayfinClient`; routing is `baseUrl` only (`''` for same-origin Vite proxy, absolute URL in Fabric). The owner admin email is `RAYFIN_PUBLIC_OWNER_ADMIN_EMAIL` in `rayfin/.env`. `rayfin env` projects it to `VITE_RAYFIN_OWNER_ADMIN_EMAIL`.
6. If the user gave a Fabric workspace name, publish it. Do not only print the `up` command. From the repo root:

```sh
pnpm up-app <slug> --workspace "<workspace name>"
```

Skip `rayfin login` unless `up-app` fails as logged-out; then from `apps/<slug>` run `pnpm exec rayfin login --encryption-fallback-enabled` and retry `pnpm up-app`. `--encryption-fallback-enabled` is expected when the OS keychain is unavailable. Paste the portal URL from the CLI output into the reply. DAX only runs in that Fabric embed, not on the static hosting URL.

SQL apps only, if also binding GraphQL at init time (logged in, workspace id):

```sh
pnpm exec rayfin init . --project-name <slug> --services db --auth-methods fabric --static-hosting --dialect mssql --workspace-id <id>
```

Then re-assert `staticHosting.buildCommand` is `npm run build:fabric` if init overwrote it. Semantic-only apps skip that init. If `fabric.yaml` was not written at scaffold time, register with `vpaa-register-semantic-model` before `up`.

If no workspace was given, skip deploy and say so.

The app must boot in `PUBLIC_ADMIN_TEST_MODE` without a Fabric login.
